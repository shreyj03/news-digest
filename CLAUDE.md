# News Digest

A multi-user website: sign up, add topics, and each morning it fetches and shows fresh articles matched to those topics, on your own chosen delivery time/timezone. Anonymous visitors see a live demo account read-only.

**Stack:** React/TypeScript/Vite frontend (`web/`), Express/TypeScript API (`api/`), standalone ingestion script (`ingest/`), Postgres (`db/`).
**Status:** Milestone 5 complete plus real UX/correctness fixes and a from-scratch newspaper-style visual redesign (newsprint paper, ink, one masthead red, Playfair Display nameplate + Newsreader headlines + IBM Plex Mono data — see DECISIONS.md). Topics auto-manage their own feed on create/rename; matching is word-boundary + full transactional recompute per run; feed shows today's articles with a `stale`-flagged fallback to recent ones; 2-column uniform-height grid; live ticker sidebar via Yahoo Finance's no-key endpoint.

**Milestone 6 (deployment) — live.** Scope changed from plan.md's original "node-cron locally, EventBridge deployed" to a real free hosted deployment (user's explicit request, driven by a hard "ready before 8am" requirement local scheduling can't honestly guarantee). Deployed via the Render + Neon MCP servers directly (user connected both; Claude drove project/service creation, schema, env vars, and GitHub secrets):
- Frontend: https://news-digest-web.onrender.com (Render static site)
- API: https://news-digest-api-a1q4.onrender.com (Render free web service)
- Database: Neon project `news-digest` (`wild-brook-94486900`)
- Scheduling: originally `.github/workflows/daily-fetch.yml` (one fixed daily cron); **superseded by Milestone 8's per-user `tick.yml`**, see below
- Access: originally `SITE_PASSWORD`-gated auth on all mutating routes; **superseded by Milestone 8's real per-user accounts**, see below

Verified end-to-end live: both services deployed and responding, real DB read/write confirmed, GitHub Actions workflow manually triggered and confirmed it populates real articles, unauthenticated mutation confirmed 401, full unlock→add-topic→delete cycle exercised through the actual deployed UI via Playwright. Local dev is unaffected (all of the above is a no-op when the relevant env vars are unset).

**Milestone 7 (Polish) — also complete.** `ingest.ts` now isolates per-feed failures (a broken feed is skipped and logged, not fatal to the whole run) and dedupes cross-outlet duplicate stories (title-normalized, outlet suffix stripped) — both gaps flagged when plan.md's final-architecture section was written, fixed the same day. Existing duplicates were also cleaned up retroactively on both the local DB (29 rows) and the live Neon database (15 rows, deleted only after explicit user confirmation).

**Post-launch improvements (2026-08-27):** ticker sparklines (7-day trend line, Yahoo's already-fetched data just wasn't kept before); per-outlet diversity cap on the feed (max 3 per outlet, derived from the title suffix — not the `source` column, which is the feed name and would've capped whole topics almost to nothing, caught before shipping); a "why did this match" caption on the signal meter listing which keywords actually hit — native `title` hover kept, plus click/tap toggles the same caption (exclusive across articles, closes on outside click) so it also works on touch devices; a 7-day history view (`GET /api/feed?date=`, UTC-based date pills in the UI); a morning digest email (`/api/fetch?email=1` via Resend) — active and confirmed delivered to the user's inbox once `RESEND_API_KEY`/`DIGEST_EMAIL_TO` were set on the API service; a branded favicon and Open Graph/Twitter preview image (`web/public/og-image.png`, 1200×630, matches the site's own masthead styling) replacing the default Vite icon and generic link-preview placeholder — confirmed working live in both a browser tab and a WhatsApp link preview; and a full redesign of the digest email itself (`sendDigestEmail()` in `api/src/index.ts`), from a bare unstyled list to a table-based HTML email matching the site's branding (paper/ink/masthead-red, double-rule dateline, `web/public/email-icon.png` — the site's icon rasterized to PNG, since SVG favicons aren't reliably supported in email clients), plus a per-article byline fix (real outlet name via `extractOutlet()`/`stripOutletSuffix()` instead of the repeated feed name) — confirmed by inspecting the actual delivered Gmail message content, not just a local preview.

The 7-day history view currently shows sparse/partial data for days before 2026-08-27 — expected, not a bug: the Neon DB was only created that day, so older `published_at` dates are just Google News' own story dates surfacing in that one-time crawl, not real day-by-day ingestion. The GitHub Actions cron's first genuine scheduled run is 2026-08-28 (~7am Pacific); a manual `workflow_dispatch` run the evening of 2026-08-27 confirmed the full pipeline (ingest → match → email) works end-to-end. History should fill in with real daily coverage from here on.

**Milestone 8 (multi-user accounts, demo mode, per-user scheduling) — built and locally verified; live deployment/migration in progress.** Real email+password accounts (scrypt-hashed, DB-backed bearer sessions) replace `SITE_PASSWORD` entirely. `topics`/`tickers` gained `user_id`; anonymous visitors see a `DEMO_USER_EMAIL`-configured account's data read-only. Scheduling redesigned mid-build per explicit user correction: not one global daily ingest with per-user delivery times, but a genuinely per-user fetch — `ingest.ts`/`match.ts` now require `TARGET_USER_ID` (no global mode left at all), and a new `POST /api/tick` (GitHub Actions every 5 minutes, replacing `daily-fetch.yml`) loops over every user and fetches+matches their own topics ~5 minutes before their own chosen local send time, then emails them at it. See [DECISIONS.md](./DECISIONS.md)'s 2026-08-28 entry for the full reasoning, including a real bug caught and fixed along the way (`pg`'s `DATE` columns come back as JS `Date` objects, silently breaking the dedup-by-date string comparison until a global type-parser override fixed it).

Locally verified: signup-claims-the-unclaimed-bootstrap-row flow, multi-user isolation (a second account starts empty and can't read/write the first account's topics), demo fallback for anonymous requests, `/api/tick`'s pre-fetch/send windows and dedup (including that a failed send correctly leaves the "already sent today" flag unset so it retries next tick), and the frontend's demo banner / login-signup form / digest-settings panel / new-account empty state all via Playwright. **Not yet done:** deploying this to Render/Neon, running the live bootstrap migration to attach the existing production data to `jainshrey2004@gmail.com`, and verifying a real end-to-end tick+email on the live site.
