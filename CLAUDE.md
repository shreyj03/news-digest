# News Digest

A website where you add topics and each morning it fetches and shows fresh articles matched to those topics.

**Stack:** React/TypeScript/Vite frontend (`web/`), Express/TypeScript API (`api/`), standalone ingestion script (`ingest/`), Postgres (`db/`).
**Status:** Milestone 5 complete plus real UX/correctness fixes and a from-scratch newspaper-style visual redesign (newsprint paper, ink, one masthead red, Playfair Display nameplate + Newsreader headlines + IBM Plex Mono data — see DECISIONS.md). Topics auto-manage their own feed on create/rename; matching is word-boundary + full transactional recompute per run; feed shows today's articles with a `stale`-flagged fallback to recent ones; 2-column uniform-height grid; live ticker sidebar via Yahoo Finance's no-key endpoint.

**Milestone 6 (deployment) — code ready, not yet live.** Scope changed from plan.md's original "node-cron locally, EventBridge deployed" to a real free hosted deployment (user's explicit request, driven by a hard "ready before 8am" requirement local scheduling can't honestly guarantee). Built: `render.yaml` blueprint (API web service + static frontend on Render), SSL-aware `DATABASE_URL` support for Neon, a `SITE_PASSWORD`-gated auth layer on all mutating routes (`X-Site-Password` header, `POST /api/auth`, localStorage-backed "Unlock to edit" control), a `FETCH_SECRET`-gated path into `/api/fetch` for automation, and `.github/workflows/daily-fetch.yml` (free GitHub Actions cron, pinned to land at/before 7am Pacific year-round). All of this is a no-op locally (unset env vars), verified not to regress local dev. **Still needed — the user's own account-setup steps** (I can't create accounts or click through dashboards for them): create a free Neon project and apply the schema, deploy the Render blueprint and fill in its env vars, add the two GitHub Actions secrets. Full steps in README.md's "Deployed version" section. Once live, verify end-to-end (curl the deployed API, exercise the UI including the password gate, manually trigger the GitHub Actions workflow once) before trusting the unattended 7am run.

See [plan.md](./plan.md) for the full build order, [DECISIONS.md](./DECISIONS.md) for why things were built the way they were, and [README.md](./README.md) for how to run it locally.

**Local dev note:** `.claude/settings.local.json` has a `SessionStart` hook that auto-starts the Postgres container, API, and frontend dev server if they're not already running — you shouldn't need to start them by hand unless that hook is missing or disabled.
